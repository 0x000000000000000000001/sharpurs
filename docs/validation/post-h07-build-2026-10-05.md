# Post-H07: reliable public build entrypoints — 5 October 2026

**Validated.** The public npm build now uses the same tool-selection policy and
build commands as the aggregate checks. The completed H01–H07 cycle remains at
100/100 points; this is a separately recorded maintenance follow-up.

## Reproduced failure

Before the change, `npm run build` exited 1 with:

```text
There's no "spago.dhall" in your current location.
```

npm injected an ancestor's `node_modules/.bin` before the selected Spago 1.0.3,
causing the legacy executable to handle the `spago.yaml` project. The nested
`prepare` hook used that same public build script.

## Implementation

- [`scripts/build.mjs`](../../scripts/build.mjs) owns the compile and bundle
  commands. The npm script, `prepare`, `bin/test -c` and `bin/modtest -c` use that
  entrypoint; the aggregate imports its named build steps and retains separate
  step logs/results.
- [`toolEnvironment`](../../scripts/support/process.mjs) prefers local tools and
  the caller's selected PATH over ancestor npm bins. Existing paths are
  canonicalized for comparison, so aliases such as macOS `/var` versus
  `/private/var` cannot reintroduce an ancestor executable.
- `SPAGO` selects an executable directly, including a path containing spaces.
  Build failure stops before bundling; compile/bundle exit codes and diagnostics
  propagate through the public npm command.

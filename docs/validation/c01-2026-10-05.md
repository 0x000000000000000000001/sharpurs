# C01 — checked fixture-runner lifecycle — 5 October 2026

**Validated: 15/100 points (15%), one of eight cycle-3 passes complete.**

## Characterized behavior

The starting runner checked compiler exit statuses, but several preparation and
cleanup commands could fail while execution continued. Isolated command shims
reproduced successful fixture summaries after failed source/foreign/companion
copies, stale-output removal, clean-cache removal and lock-owner writes. A real
directory at `spago.yaml` also failed configuration writes without stopping the
compiler. A failed `cd` allowed Spago to run in the caller's directory.

Cache-removal failure could leave the mutated cache in place and copy the saved
directory inside it. Restore-copy failure already returned exit 1, but only after
printing a successful summary. Lock-release failure could still exit 0. A
competing invocation created `src/` before checking the existing lock.

## Implementation

[`bin/test`](../../bin/test) now has named ownership, snapshot, workspace,
fixture-preparation, execution and finalization stages. `runner_io` preserves the
command's original diagnostic and adds operation context and its nonzero status.
Each caller stops explicitly; correctness does not depend on Bash's conditional
`errexit` semantics.

- The lock is acquired before creating fixture inputs. Lock ownership and snapshot
  completeness are tracked independently, including failures during startup.
- A new configuration is written in the owned lock directory, then published
  with a checked rename. Existing configuration files retain their contents.
- Source/JS/companion copies, cache/output removals, provenance-file reads and
  directory changes must succeed before the dependent operation. Empty companion
  directories are accepted without attempting to copy a literal `*`.
- Finalization runs once. An incomplete snapshot leaves the original cache alone;
  a restore failure retains the complete backup and prints its path. Failed cache
  removal prevents the restore copy. Lock-release failures propagate.
- The final success summary follows successful restoration and lock release.
  Handled SIGINT/SIGTERM retain exits 130/143 unless cleanup itself fails, which
  returns 1. Fixture-selection contracts and compilation commands are preserved.

# C06 — optimized boxed templates — 6 October 2026

**Validated: 80/100 points (80%), six of eight cycle-3 passes complete.**

## Implementation

Three production files change:

- [`Optimized.purs`](../../src/Sharpurs/Optimized.purs) folds `Boxed.lambda` over
  optimizer levels, keeping the body as an `FsExpr` until the shared template renders
  it. The old local lambda-string assembly and printer import are removed.
- [`Names.purs`](../../src/Sharpurs/Names.purs) owns
  `optimizedLocal :: Level -> String`, the sole production definition of
  `sharpurs_o_` lexical names.
- [`IntKernel/CodeGen.purs`](../../src/Sharpurs/IntKernel/CodeGen.purs) uses that
  same owner when unboxing the native kernel's outer entry arguments. The kernel's
  private `sharpurs_i_` namespace remains distinct.

The literal review found one additional exact template match: the optimized Int
literal now uses `Boxed.box (FsRawExpr (show value))`. This preserves `(box (VALUE))`
exactly. Substituting `FsLitInt` would instead emit `(box VALUE)`; passing that
already-boxed AST to `Boxed.box` would introduce another box. String and Boolean
literals continue to use their existing AST constructors.

The existing `Boxed` templates need no modification. Admission, lexical scope,
type evidence, binding priority and native-loop recognition retain their previous
code. The right fold keeps binder order and a boxed closure at every curry stage.
The [compiler guide](../compiler.md#optimized-object-envelopes-around-local-int-kernels)
documents these boundaries and their owners.

# H02 — explicit F# call conventions — 2 October 2026

**H02 is validated: 40/100 points, 2 of 7 milestones in maintenance cycle 2.**
The next milestone is H03, separating ADT validation from rendering.

## Changes

- `FsDirectApp` carries `PassValues` or `UnboxArgumentsBoxResult`. These describe
  both argument and result adaptation. `FsAst` explicitly exports the AST and
  the `directCall` / `boxedNativeCall` constructors.
- `Printer` has one expression renderer. `printExprInline` is a compatibility
  alias of `printExpr`; the global `ConvertArguments` / `PassArguments` choice
  and its recursive propagation are removed. A nested call keeps its own adapters.
- `CodeGen` selects the convention when constructing each call. Ordinary value
  declarations retain their existing boundary; object workers and boxed template
  inputs use direct values. Constructor saturation and local partial application
  are resolved before constructing their arguments. Generic fallback arguments
  are constructed only when that route is selected.
- `Case` retains source bodies until their placement is known. Named expression/
  object callbacks preserve scrutinees, guards, structural branches and boxed
  catch-all bindings without changing an already-constructed AST.
- `Boxed` uses the single renderer. Its eta adapters construct direct calls, and
  non-nullary native factories construct boxed native calls. Nullary factories
  retain their existing named-value syntax.
- The printer suite reuses identical AST objects in nine placements, covering
  native, object, adapted and mixed nested calls. It also checks named values,
  reusable partials, a returned function and left-to-right argument evaluation.

The [compiler guide](../compiler.md#constructing-a-call) documents the invariants,
boundary constructors and exception contracts. The
[test guide](../testing.md#call-conventions) describes the relevant suites.

# H01 — public names and exact string keys — 2 October 2026

**H01 is validated: 20/100 points in maintenance cycle 2.** Its scope is public
naming, string/record-key emission and their regression coverage. The next
milestone is H02, explicit F# call conventions.

## Changes

- `Names` owns public qualification/escaping, generated module names and worker
  suffixes. Declarations, references, constructor patterns, collision checks,
  FFI wrappers/stubs and the entrypoint use these functions. Qualification occurs
  before escaping; a constructor named `System` therefore agrees with its callers.
- The native FFI name remains distinct from the public PureScript-facing name.
  Primed/Unicode names, Unicode F# headers, C# casing and `@`-escaped method names
  are exercised through the real compiler. Native members needing F# quoting use
  double backticks without changing their spelling.
- Record creation, update and access escape string keys. Patterns preserve lone
  UTF-16 surrogates with `HasPropUtf16`/`LitStringUtf16`: F# replaces their literal
  escapes with `U+FFFD`, and active-pattern arguments cannot use a `new String`
  expression. Ordinary keys and string patterns keep their existing matchers.
- `test:names` compiles seven real TAST modules, runs the production CLI with
  `Naming.Entrée`, then builds/runs a mixed F#/C# project. An independent native
  checker verifies all four record operations on twelve exact keys, generated
  names, native calls and reusable missing-FFI partials.

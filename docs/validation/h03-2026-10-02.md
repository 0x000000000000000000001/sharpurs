# H03 — ADT validation/rendering boundary — 2 October 2026

**H03 is validated: 55/100 points, 3 of 7 milestones in maintenance cycle 2.**
The next milestone is H04, making project outputs and filesystem errors explicit.

## Changes

- `AdtKernel.Lower` validates optimized bodies and delegates their F# syntax to
  `Emit`: literals, calls, field projections, constructor-tag tests, binary
  operations, lexical bindings, branches and failures. Constructor application
  and local names already belonged to `Emit`.
- `Analysis.primitive` returns a named `Operation` with its operand/result type
  contract. Its ten admitted operations have no F# spelling in the analysis;
  `Emit.operator` owns the exhaustive syntax mapping.
- Body templates use named records where arguments have distinct roles:
  `target`/`arguments`, `constructor`/`value`/`index`, `operation`/`left`/`right`,
  `level`/`nativeType`/`value`/`body`, and `cases`/`fallback`. Branches name their
  condition and body instead of passing positional string pairs.
- Lowering retains the existing nested type checks, lexical-level rules,
  constructor identity/field checks, exact saturation and guarded-target
  selection. `Emit` accepts checked children and does not inspect source or
  optimized expressions.
- The new `test:adt-lowering` suite has small typed lowering scenarios and
  separate static F# support/assertion fixtures. It supports an immutable
  historical API bundle through `ADT_LOWERING_ORACLE`.

The [compiler guide](../compiler.md#changing-an-adt-body-template) describes the
boundary and a field-projection template change. The
[test guide](../testing.md#adt-lowering-differential-replay) documents bundling
the before API, the differential replay and retained artifacts.

### Lowering differential

The historical API was bundled from the validated H02 compiled output before
rebuilding the modified compiler. It includes the complete lowering dependency
graph. Both compilers construct each scenario with their own PureScript classes;
the oracle does not import current dependencies or receive mismatched runtime
constructors.

The final 108-scenario factory and both static F# files have identical source
hashes in the before and after runs. The test checks expected admission/rejection
for both compilers, then compares every outcome and admitted body byte-for-byte.
The retained complete `Generated.fs` files also have identical hashes.

Coverage includes all ten operations and contradictory operand/result types,
guarded/whole-native/self/constructor calls, partial and over-applied rejection,
constructor identities, field labels/indices/types, lexical scope and increasing
levels, branches and escaped failure messages. Runtime checks cover Int limits,
subtree identity, one-time let evaluation, argument order, branch selection,
Boolean short-circuiting and precise exception wrappers/causes. Existing real
TAST suites complement these small inputs with source dependencies, public/partial
applications, native selection and full producer/consumer behavior.
